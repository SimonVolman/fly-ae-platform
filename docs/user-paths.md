# fly.ae user paths and acceptance tests

Этот документ — единый реестр пользовательских сценариев fly.ae. ID являются
постоянными: существующий path нельзя перенумеровывать после появления тестов,
аналитики или bug reports. Новые paths получают следующий свободный номер.

## Обозначения

- `UP-001` — ID пользовательского path;
- `UP-001-T01` — ID теста внутри path;
- `P0` — блокирует основной релиз;
- `P1` — важный негативный или recovery-сценарий;
- `IMPLEMENTED` — поддерживается текущими Web и backend;
- `PARTIAL` — backend или Web поддерживает только часть сценария;
- `PLANNED` — согласованный сценарий, который ещё не реализован.

| ID | Приоритет | Пользователь | Path | Статус |
|---|---:|---|---|---|

| `UP-003` | P0 | Новый пользователь | Первая загрузка без email, PDF до 10 MiB | IMPLEMENTED |

| `UP-007` | P0 | Владелец | Удаление документа и отзыв ссылки | IMPLEMENTED |
| `UP-008` | P1 | Новый пользователь | Неверный, истёкший или повторный OTP | IMPLEMENTED |

## UP-001 — первая загрузка через email OTP

**Предусловия:** пользователь не авторизован; категории доступны; PostgreSQL и
S3-совместимое хранилище запущены.

```text
Открыть fly.ae
→ выбрать category
→ указать MSN
→ ввести email
→ ввести OTP
→ принять Terms и Privacy
→ выбрать PDF до 100 MiB
→ загрузить
→ дождаться APPROVED
→ получить share-ссылку
```

### Тесты

- `UP-001-T01` — валидный PDF проходит полный flow до `APPROVED`.
- `UP-001-T02` — документ появляется в My Documents.
- `UP-001-T03` — `shareUrl` отсутствует до `APPROVED` и появляется после него.
- `UP-001-T04` — загруженный PDF доступен по публичной share-странице.

## UP-002 — повторная загрузка без OTP

**Предусловия:** в браузере есть действующая bearer session.

```text
Открыть fly.ae
→ выбрать category и MSN
→ выбрать PDF до 100 MiB
→ загрузить без повторного OTP
→ получить share-ссылку
```

### Тесты

- `UP-002-T01` — действующая session не открывает OTP dialog.
- `UP-002-T02` — второй документ принадлежит тому же пользователю.
- `UP-002-T03` — оба документа отображаются в My Documents.

## UP-003 — первая загрузка без email

**Статус:** implemented guest-flow.

```text
Открыть fly.ae
→ выбрать category
→ указать MSN
→ принять Terms и Privacy
→ выбрать PDF до 10 MiB
→ получить guest access token
→ загрузить
→ дождаться APPROVED
→ получить share-ссылку
```

Guest token должен давать доступ только к созданному документу. My Documents и
документы других владельцев недоступны. Лимит равен `10 485 760` байт.

### Тесты

- `UP-003-T01` — guest загружает валидный PDF меньше или равный 10 MiB без email.
- `UP-003-T02` — guest получает статус и share-ссылку своего документа.
- `UP-003-T03` — guest не получает доступ к общему My Documents.
- `UP-003-T04` — guest token не открывает чужой документ.
- `UP-003-T05` — файл больше 10 MiB блокируется до создания upload session.
- `UP-003-T06` — backend возвращает `413`, если frontend-проверка была обойдена.

## UP-004 — сохранение guest-документа

```text
Получить guest share-ссылку
→ нажать Save to My Documents
→ ввести email и OTP
→ привязать документ к User
→ открыть My Documents
```

### Тесты

- `UP-004-T01` — успешный OTP переносит документ из guest ownership в User.
- `UP-004-T02` — документ появляется в My Documents без повторной загрузки.
- `UP-004-T03` — существующая share-ссылка продолжает работать.
- `UP-004-T04` — документ нельзя повторно привязать к другому пользователю.

## UP-005 — My Documents

### Тесты

- `UP-005-T01` — список содержит только документы текущего пользователя.
- `UP-005-T02` — отображаются filename, category, MSN, size и status.
- `UP-005-T03` — Copy link доступен только для `APPROVED`.
- `UP-005-T04` — My Documents доступен на desktop и mobile.

> Текущий mobile UI не проходит `UP-005-T04`: desktop navigation скрывается без
> замены на mobile menu.

## UP-006 — публичная share-ссылка

### Тесты

- `UP-006-T01` — share-страница открывается без авторизации.
- `UP-006-T02` — отображаются filename, category, MSN и size.
- `UP-006-T03` — Download PDF возвращает исходный PDF.
- `UP-006-T04` — повторное открытие выдаёт новый короткоживущий download URL.
- `UP-006-T05` — случайный или отозванный token возвращает `404`.

## UP-007 — удаление и отзыв ссылки

### Тесты

- `UP-007-T01` — владелец подтверждает удаление документа.
- `UP-007-T02` — документ исчезает из My Documents.
- `UP-007-T03` — объект удаляется из S3.
- `UP-007-T04` — share token после удаления возвращает `404`.
- `UP-007-T05` — другой пользователь не может удалить документ.

## UP-008 — негативные OTP-сценарии

### Тесты

- `UP-008-T01` — неверный OTP не создаёт session.
- `UP-008-T02` — после пяти неверных попыток OTP блокируется.
- `UP-008-T03` — истёкший OTP не принимается.
- `UP-008-T04` — использованный OTP нельзя применить повторно.
- `UP-008-T05` — новый OTP отменяет предыдущий.
- `UP-008-T06` — rate limit возвращает `429` и `Retry-After`.

## UP-009 — проверка PDF

### Тесты

- `UP-009-T01` — Web блокирует файл без расширения `.pdf`.
- `UP-009-T02` — Web блокирует MIME, отличный от `application/pdf`.
- `UP-009-T03` — авторизованный пользователь не может загрузить больше 100 MiB.
- `UP-009-T04` — guest не может загрузить больше 10 MiB.
- `UP-009-T05` — backend удаляет объект с неверным фактическим размером.
- `UP-009-T06` — файл без заголовка `%PDF-` получает `FAILED/INVALID_PDF`.

## UP-010 — прерванная загрузка

### Тесты

- `UP-010-T01` — ошибка части переводит Web в понятное error state.
- `UP-010-T02` — Abort завершает multipart session.
- `UP-010-T03` — пользователь может начать новую загрузку после Abort.
- `UP-010-T04` — refresh/browser restart не обещает resume в V0.

## UP-011 — истёкшая session

### Тесты

- `UP-011-T01` — backend возвращает `401` для истёкшего token.
- `UP-011-T02` — Web очищает старую session.
- `UP-011-T03` — Web открывает OTP dialog.
- `UP-011-T04` — после OTP пользователь возвращается к прерванному действию.

Текущий Web требует доработки для тестов `UP-011-T02`–`UP-011-T04`.

## UP-012 — изоляция владельцев

### Тесты

- `UP-012-T01` — пользователь A не может получить документ пользователя B.
- `UP-012-T02` — пользователь A не может подписывать upload parts документа B.
- `UP-012-T03` — пользователь A не может завершить или отменить upload B.
- `UP-012-T04` — пользователь A не может удалить документ B.
- `UP-012-T05` — недоступные ресурсы возвращают `404`, не раскрывая владельца.

## Правило для bug reports

Bug должен ссылаться на path и тест:

```text
[UP-005-T04] My Documents отсутствует в mobile navigation
```

Если дефект затрагивает весь path, используется только ID path:

```text
[UP-003] Guest upload не создаёт upload session
```
